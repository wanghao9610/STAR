## 3. Findings

### Major

- **F1** `.agents/hooks.json:31`, `.gemini/antigravity-cli/hooks/star_involve_gate.sh:22`: the Antigravity edit gate never fires.
  - Rule: conventions §7.7 and §13 (Antigravity skips edit prompts at `INVOLVE=low`). The Antigravity hooks docs list the file tools as `write_to_file`, `replace_file_content` and `multi_replace_file_content`, each taking a path argument named `TargetFile`.
  - Evidence: `"matcher": "edit_file|write_file"` and `star_json_field 'toolCall.args.Path'`.
  - Fix: set the matcher to `write_to_file|replace_file_content|multi_replace_file_content` and read `toolCall.args.TargetFile`.
- **F2** `.gemini/antigravity-cli/hooks/star_involve_gate.sh:38`: even when it fires, the gate cannot skip the prompt.
  - Rule: same as F1. The docs say `allow` "delegat[es] to the next hook or default policy", while `auto_approve` "automatically approves the tool call when the default policy would otherwise prompt".
  - Evidence: `printf '{"decision":"allow","reason":"INVOLVE=low"}'`.
  - Fix: emit `"decision":"auto_approve"`.
- **F3** `.claude/hooks/star_commit_guard.sh:156`: git commands are recognised only when `git` is the segment's first word.
  - Rule: the header (lines 9–15) and conventions §1, under "The guard".
  - Evidence: `case "${tok[0]}" in git|*/git) ;; *) continue ;; esac`.
  - Reproduced: `env git add -A`, `{ git add -A; }`, `if true; then git add -A; fi` and `git stage -A` each get no guard decision. In Claude Code at `INVOLVE=low`, `star_bash_gate.sh` then returns `allow`.
  - The same logic is in every harness copy of the guard.
  - Fix: dispatch git from the token that the launch walker (lines 118–129) already reaches. Add `sudo`, `xargs`, `then`, `do`, `else`, `{` and `!` to that walker's skip set, and treat `stage` as `add`.
- **F4** `.claude/hooks/star_bash_gate.sh:85`: the command-position walker stops at shell keywords.
  - Rule: the header (lines 6–11) says red lines keep their prompt at every level.
  - Reproduced: plain `git push origin main` gets no decision (it prompts), but `if true; then git push origin main; fi` gets `allow`. The same mechanism covers `for … do rm -f …; done` and `{ rm -rf build; }`.
  - Fix: add `then`, `do`, `else`, `elif`, `{`, `!`, `eval` and `setsid` to the skip list.
- **F5** `.claude/hooks/star_commit_guard.sh:127`: the STOP-line launch walker skips only all-digit arguments.
  - Rule: the header (lines 25–30) and conventions §2 say a prepared launch runs only after its review.
  - Reproduced: with `wkdrs/r1/EXEC_LOG.md` present and no review, `bash execs/scpts/r1.sh` is denied, but `timeout 12h bash execs/scpts/r1.sh` and `source execs/scpts/r1.sh` pass.
  - By the same mechanism, `.`, `sudo` and `1>wkdrs/r1/.await` also pass.
  - Fix: skip duration tokens matching `^[0-9]+(\.[0-9]+)?[smhd]?$`, add `.`, `source` and `sudo` as wrappers, and accept `[0-9]*>` redirects in the `.await` scan.
- **F6** `.claude/hooks/star_commit_guard.sh:78`: the 10 MB staged-size check reads only the main checkout's index.
  - Rule: the header (lines 15–17), with worktree runs per §11.8.
  - Evidence: `git -C "${root}" diff --cached --name-only -z`.
  - Effect: a checkpoint staged in `../<root>--wt/<run>` is committed unchecked. Conversely, a large file staged in the main checkout blocks an unrelated worktree commit. This applies to every harness copy.
  - Fix: resolve the repository that the commit targets (its `-C` argument or a preceding `cd`) and size that index.
- **F7** `.claude/hooks/star_model_id.sh:142` (also `.qwen/hooks/star_model_id.sh:64`): the injected resolver command leaves the model id and transcript path unquoted.
  - Rule: conventions §8 says the resolver is run as written and its output copied.
  - Reproduced: `zsh -c 'echo claude-opus-5[1m]'` fails with `no matches found`. With a 1M-context model on a zsh Bash tool, the resolve fails and the skill records `unrecorded`. A `HOME` containing spaces breaks the command too.
  - Fix: build the arguments with `printf %q`, as `.codex/hooks/star_model_id.sh:165-166` already does.
- **F8** `.agents/skills/star-code-reviewer/scripts/review_state.sh:69`: `plan_hash` closes the frontmatter only on an exact `---` line and never detects an unclosed fence.
  - Rule: star-code-reviewer SKILL.md says plan bodies are bound into the review, and `check` returns zero only for a current review.
  - Reproduced, with a plan whose body contains "Train with lr 0.1", edited to "lr 0.9":
    - With an exact closing `---`, the edit makes `check` exit 1 (stale), as intended.
    - With a closing `--- ` (trailing space), `check` still exits 0 (current).
  - Body headings, prose and tables drop out of the hash. Only YAML-shaped lines kept under the frontmatter rules remain.
  - `validate.sh` trims fences, so nothing else flags the plan.
  - Fix: match `/^---[[:space:]]*$/` for both fences, and add `END { if (front) exit 2 }`.
- **F9** `execs/configure.sh:340` versus `execs/update.sh:862`: once any tier key stamps a manifest, `update.sh --diff` reports `differs` forever and exits 2.
  - Rule: the `--diff` contract (`update.sh:359-362`) says it exits 0 when everything matches.
  - Evidence: `--diff` compares stamped project files byte-for-byte with unstamped upstream files.
  - Fix: stamp a scratch copy of the upstream file before the `cmp`, or ignore the stamped frontmatter fields.
- **F10** `execs/update.sh:1130`: `--adopt` runs whatever `execs/configure.sh` the target project already has, including a non-STAR file it reported as kept.
  - Rule: the `--adopt` contract (`update.sh:370-373`, 1136) says it never overwrites and modifies nothing that was already there.
  - Fix: run it only when `cmp -s` matches `${SOURCE_DIR}/execs/configure.sh`, and otherwise log that stamping was skipped.
- **F11** `.github/scripts/equiv_check.sh:48`: each work copy is a `git archive` export without `.git`.
  - Effect: check 26 (`check_consistency.sh:1672`, `git ls-files .star/memory`, added in `612b5953` on 2026-09-11) fails in every case, including the clean baseline `f00`. The tool therefore exits 1 in both modes. CI does not run it.

## 5. Good Practices

- `review_state.sh check` fails closed in every traced non-current state except F8 and F34, and the commit guard denies launches when the review helper is missing or errors.
- `port.sh --check` makes generated-tree drift impossible to merge silently.
- The Codex `star_model_id.sh` already quotes its injected command with `%q`, which is the pattern F7 needs.
