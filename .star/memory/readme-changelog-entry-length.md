两份 README 更新日志里，每条发布条目最多三句话，能更短就更短。

**Why:** 更新日志是拿来扫的，不是拿来读的。一条几百字的段落把「这一版到底换了什么」埋进实现细节里，读者常常一条都读不完就划走了。细节各有各的家——commit message、标签注释、规约正文——更新日志只负责让人一眼认出这一版的变化。
**How to apply:** 三句话通常摊成「这版改了什么 / 关键约束或例外 / 顺带一提」。`- **[vX.Y.Z](tag)** (date) — ` 这段前缀原样保留，只重写破折号之后的正文；两份 README 一起改，英文数句号、中文数「。」。新版本一开始就按这个长度写，不要先写长再回头压缩。这条与 `readme-changelog-three-open`（只展开最新三条、其余折叠）是两条独立的偏好，同时生效——注意那一条的理由里提到「每条都是一整段长文」，那个前提已经不成立，但折叠本身仍然要做。
