# Refs 评分表 — 一次合格的文献综述要满足什么

打分对象有两个：逐篇分析笔记，以及 `reference.bib` 及其 index。红线不可谈判；质量标准则决定这是一个文献基础还是一份标题清单。

## 红线（违反即本轮作废）

1. 每个 bib 字段都能追溯到本次运行抓回并缓存在 run 目录里的记录（`references/source_policy_zh.md`）。没有凭记忆的字段，没有推断的字段，没有"明显应该是这个"的填充。
2. 每个 citekey 在 `refs_index.md` 里都有 provenance 行：来源、记录 URL、抓取日期。
3. 每一条都能用一句话说清它与本方法主题的关系。为凑数塞进关系松散的工作，比如实报 43 条更糟。
4. 每篇核心论文都有分析笔记；每篇笔记的 citekey 都在 `reference.bib` 里。
5. 除 `metds/refs/**` 与 `wkdrs/refs_<date>/**` 外不写任何文件。

## 核心论文的挑选（5–10 篇）

一篇论文靠**近**拿到笔记，不是靠名气：

- **直接重叠** —— 同一个任务，或同一机制用在别处。一篇 2019 年正好在做本方法这件事的论文，胜过一篇 2024 年顺带提了一句的综述。
- **定位价值** —— 本方法必须与之划清界限的工作；审稿人一定会问到的那篇。
- **baseline / 基准地位** —— 实验将要对比的对象。
- **新旧** —— 相关性相当时的 打平时的取舍依据，绝不是主轴。

每条候选都带一句话理由。一句话说不清为什么要读它的，就不是核心论文。

## 分析笔记

每篇笔记（`assets/ref_analysis_template_zh.md`）按这些标准打分：

- **具体胜过含糊。** "在 400M 图文对上做对比学习"——不是"利用了大规模数据"。数字来自论文，数据集写明，baseline 写明。
- **方法可复述。** 没读过原文的人读完能说出它做了什么、为什么应该有效。只写关键公式，符号要定义。
- **与本项目的关系才是重点。** 泛泛的摘要网上到处都是；笔记值钱在 §5——共同点、差异点、可借鉴、以及它让本项目能立什么。一个换个项目也照样成立的 §5，就是失败的 §5。
- **对读到什么程度诚实。** 至少读摘要、intro、方法和主结果表。若只够到摘要和 intro，`depth:` 就如实写——承认自己浅的笔记有用，装深的没用。
- **主张是论文的，不是你的。** 数字照论文报（指标 + 数据集 + split）。绝不外推，绝不跨不可比设定做比较，不确定的标 `[unverified]`。

## 笔记收集器的返回格式

Step 3 的精读分派出去时,只读 subagent 返回的就是这一份。`assets/ref_analysis_template_zh.md` 是那个*文件*的形状,不是受托者的返回格式:它要求填 `read_on`,要求填 `model_id` / `model_trail`——那属于真正写下文件的那次会话（conventions §8）——还要求填 `category`,而 category 要到 Step 6 才从整个池子推导出来,此刻根本不可能存在;§7 的延伸阅读同理,它要的是 `reference.bib` 里已有的 citekey,而那个文件 Step 5 还没建起来。收集器把这些填上,写下的就是一份可被证明为假的记录。

一个收集器一篇论文。返回:

- `note_body`——模板的 §1、§2、§3、§4、§6,填好。**§5 与 §7 留空**:§5 需要本项目的方法上下文,而这正是这篇笔记存在的理由;§7 要的是 Step 5 之前还不存在的 `reference.bib` 里的 citekey。
- `title` / `venue` / `year`——完全照论文自己页面上的写法。
- `links`——paper / code / project,或 `none found`。
- `depth`——它实际读到了哪一层。
- `depth_evidence`——`{sections_reached: [...], results_table: <表题加一行,原文照录>}`,或 `none reachable`。
- `relation_material`——`[{claim, where}]`:给 §5 用的原料,绝不是 §5 本身。
- `cited_works`——这篇论文相关工作章节引的东西,趁论文已经打开时顺手采下来。

别的都不返回:不填 frontmatter 溯源、不填 `category`、不填 `read_on`、不写 §5。文件全部由主 agent 来写。

## Survey 收集器的返回格式

Step 10.4 的阅读分派出去时,只读 subagent 返回的就是这一份。一个收集器一篇论文。返回:

- `facts`——`[{claim, where}]`:论文做了什么、说了什么、报了什么,每条都系在它出自的章节或表格上。
- `title` / `venue` / `year`——完全照论文自己页面上的写法。
- `links`——paper / code / project,或 `none found`。
- `depth`——它实际读到了哪一层,用笔记的深度词汇（`method-and-results` / `abstract-and-intro`）。
- `depth_evidence`——`{sections_reached: [...], results_table: <表题加一行,原文照录>}`,或 `none reachable`。
- `failures`——`[{host, error, retries}]`。

别的都不返回:不归支（分类体系由主 agent 对着整个池子定）、不写成段的正文、不填任何 frontmatter 字段。文件由主 agent 来写。

## reference.bib 的组织

- **3–8 个类别。** 少于 3 类算不上分类；多于 8 类把领域切碎了。
- 类别从实际收集到的这批文献的语义里长出来——标题、任务、机制——不是事先强加的分类体系。
- 命名要贴合这批文献：`Open-vocabulary detection`，不是 `Related methods`。
- 每类一个 `%%` 块头：类名、条目数、一行范围说明。组内按年份升序、再按 citekey 排序。
- 每条恰好归入一类。确实两头不靠的进最后的 `Other / cross-cutting` 块，占比封顶约 10%——超了说明类别划错了，不是论文有问题。

## refs_index.md

- provenance 表覆盖 100% 的条目。
- 类别表的计数之和等于条目总数。
- 待人工核对清单即使为空也要在（写"无"）——整节缺失读起来就像"什么都没出问题"。
- 自拟缩写（†）与 arXiv-only（‡）要标出来。

## 综述文档（survey 模式）

`<slug>_survey.md` 按这些标准打分：

- **分类体系有出处、有声明。** 一句话写明划分轴，被舍弃的轴写在旁边；轴下 3–8 支，上面的类别规则原样适用。该话题已有综述时从 1–3 篇的体系起步——改造，绝不整套照搬。至多两层；每篇恰好落在一支上，跨支的论文在对比表里与别支相遇，不在正文里出现两次。
- **每支是综合，不是清单。** 每支一节，说清这批工作共享什么、在哪分岔——绝不逐篇罗列摘要。
- **阅读层是证据上限。** 精读层（deep，读到 `method-and-results` 或更深）是对比表唯一的行来源、转引数字唯一的出处；泛读层（abstract）的论文可以归支、可以用一句话刻画；记录层（record）的论文只凭记录的事实被点名，绝不刻画。frontmatter 里的各层计数必须是实数。
- **表格的列要同时挣到三样**：能区分（各行的值真的不同）、每行都能从抓回的来源填上（填不上的写 `—`）、回答读者真会面对的一个取舍。重复分支归属的列、放自由文本摘要的列，都是关在笼子里的正文。
- **每条论断有依据。** 非显然的论断带行内 `[@key]`，能在带注引用表里解析；数字连着数据集与指标；缓存来源撑不住的，删掉或标注为本综述自己的推断。
- **计数账在场**：found → deduplicated → screened → tiered，加上排除了什么、为何排除。
- **它得配得上"综述"二字。** 不足约 30 篇、或没有精读层、或围绕单个项目的定位来组织——那是 related-work 笔记（`synthesize` 的产物），运行就该这么说，而不是注水。

## 聊天摘要

约 500 字内：方法来源、写了哪些笔记、条目数与各类别计数、自查结果、需要人工处理的部分、下一个 skill。数要报实——缺口就按缺口报。survey 模式的摘要改按 Step 10.8 来。
