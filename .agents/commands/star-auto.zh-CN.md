# 朝目标自动推进工作流

> 本文件是 [`star-auto.md`](star-auto.md) 的中文对照版。运行时以英文原文件为准。

用户敲下了 `star-auto`——这次调用运行的就是本文件。敲下它即规约 §10.7 所定义的自动授权：本次运行追逐目标期间，每个下一步动作点名的 skill 都可以直接启动，包括只许显式调用的那七个；备好的红线命令也可以直接启动而非交回。授权只覆盖"启动 skill"与"启动备好的命令"两件事；被启动的运行，行为与用户亲手点名时完全一致。

调用形状：`star-auto <目标> [stop=<停止线>] [involve=<档位>]`。

## 解析调用

- 先剥掉 `involve=<档位>`，只取停止线文本之外的——`stop=` 之前的，或整个调用末尾的那个 token；停止线里出现的同样字样是停止线文字，不是 token（规约 §7.7）。什么都没设档位时——没有 token、`.env` 里也没有 `INVOLVE`——本次运行解析为 `low` 而非 `medium`：自主运行对自己的裁量题取标注的推荐项并逐条记录（§7.8）。必问确认点不受影响——任何档位都要问，这里也一样。
- 再剥 `stop=`：从这个 token 起到剩余文本末尾的全部内容就是停止线，用户自己的话写的自然语言——`stop=any single training over 4 hours, or any paid API call`、`stop=用卡超过 2 张就停`（中英皆可，混写也行）。**给了**，它就是本次运行不得越过的线：启动一条备好的命令之前，先陈述其预期开销并逐条对照——越线的、或无法对照判断的，照 §2 原样打印交回。**没给**，本次运行不设上限：备好的红线命令自主启动，以完成目标为先（§2 的唯一例外）。无论哪种，每次启动都连同陈述的开销记入决策记录；且授权与任何停止线都永不覆盖删除、覆盖、`sudo` 或系统级/驱动安装，以及其他不可逆动作——那些任何档位都要问（§7.7）。
- 剩下的就是目标。没有目标——问用户要；绝不从仓库里替用户猜一个。

## 循环之前

一次 grep 读出 `.env` 的 `STAR_LANG` 与 `INVOLVE`（§7.6、§7.7）。把目标变成运行可查验的判据——某个叶子要到达的 `exec_status`、必须存在的文件、报告里要出现的指标——开跑第一行写明判据、停止线（或说明没设）和解析出的档位。变不成判据的目标，先问清，不追。

## 循环

1. 经宿主原生 skill 机制运行 `star-flow-status`，取它唯一的下一步动作。
2. 启动被点名的那个：
   - 属于 agent 可拾起的八个——走宿主原生机制，完全按 §10.2–10.6 执行，并把本次运行解析出的档位以 `involve=` token 附在调用上：每次被启动的运行各自解析档位（§7.7），不带 token 的启动会退回 `.env`，而不是本次运行的默认值。
   - 属于只许显式调用的七个——授权覆盖它：先声明一行（匹配上了什么、取了哪个目标），然后派一个子代理完整读取该 skill 在本宿主的 `SKILL.md` 并遵循它，本次运行解析出的档位以同一个 `involve=` token 写进委派简报；结束时在决策记录里留一行，`匹配到什么 → 跑了什么 → 写了哪些文件`（§10.5）。
   - 一条备好的红线命令——按上面的停止线规则：启动并记录，然后等它跑完、按交接说明收取用于查验判据的输出，再回到第 1 步；等不了的命令就结束本次运行，报告写明在等什么。被用户的停止线拦下时——打印命令、停下、报告。
3. 用户点名的运行会问什么，这次运行就问什么。目标没定死就列出候选并等待（§5.2、§10.3）；必问确认点照问照等（§7.2），没有人能回答时——headless 运行——就停在那里报告，而不是替用户假设；一次启动一个工作单元（§10.4）。
4. 每次运行结束后，接着跑它点名的下一步——在本授权之下，那七个与那八个同样照跑（§10.6）——没有点名时，重跑 `star-flow-status`。
5. 失败过的动作不在同一目标上重试。失败换来的转交——一次修订、一次修复——本身就是下一步动作，跑一次；它也失败时，停下报告。

## 何处结束

在下列第一个到达处报告并停止：目标判据通过；必问的问题无人可答；命令越过用户的停止线，或已启动的命令等不了；一整轮下来目标判据比上一轮没有更近；第 5 条走投无路。最终回复写明跑了什么、每次运行写了哪些文件、目标判据的结果，以及——中途停下时——正在等待的那条确切命令或问题。两次调用之间什么都不延续：重敲这条命令就从各次运行留下的树状态续起，停止线以新调用里写的为准。

## 本命令绝不做的事

它启动 skill、启动它们备好的命令；不授予其他任何东西。它自己不写计划、不写报告、不写代码——所有产出都来自它启动的运行。一次调用一个目标；下一个目标是下一次调用。
