# 红线规则 —— agent 跑什么 vs 用户跑什么

agent 及其委派的子代理可以写代码、跑**轻量验证**。任何**重型、昂贵或不可逆**的动作都越过红线。备好确切命令；除非启动已经得到具体授权，否则写进 EXEC_LOG 的"待用户执行"区。要求实现计划、批准 EXEC_PLAN、或对命令有把握，都不是启动授权。合法的 `star-auto` 是重型或昂贵命令唯一的常驻例外：审查通过后，命令陈述的、有界成本没有越过它的 `stop=`，或本次调用没有设置停止线时，其启动器可以运行备好的命令。普通运行中，用户另行明确指示也可授权同一条确切命令或边界清楚的一类启动；引用并沿用那条指示，不重复询问。两种授权都不覆盖成本无法对照用户所设上限判断的命令，也不覆盖删除、覆盖、`sudo`、系统/驱动安装或其他不可逆动作；后面这些动作必须由用户另行明确授权到具体目标。

## agent 执行（轻量验证）

- 单元测试 / 跑通性检查、import 检查、极小 batch 的一次前向。
- 小规模、**不微调**的推理,在小子集上——例如 MVP 完成判据:"不训练、小子集、替换文本输入做对比"。
- 空跑、配置校验、shape / dtype 检查、几步过拟合的合理性检查。
- 任何在适度资源上几分钟内就能跑完的动作——生成输出及持久执行记录只写入 `wkdrs/<run>/`,中间工作文件只写入 `tasks/<plan-name>/`。

## 越过红线 → 交给用户

- **长时或多卡训练 / 微调**——任何完整训练 run。
- **大开销 API 调用**——按次计费的大批量 LLM/VLM 推理(如在全量数据集上生成描述)。
- **全量评测**——耗时数小时或占用可观算力。
- 任何会**覆盖用户可能想保留的已有产物**,或把生成的 run 产物写到 `wkdrs/<run>/` 以外的动作。常规向 `tasks/<plan-name>/` 写入中间工作文件不越过红线。先解析确切目标；覆盖得到明确授权前，保留已有产物。
- 任何你**无法界定开销或耗时**的动作——拿不准就当越过红线处理。

## 怎么交接

对每个越过红线的动作,写进 EXEC_LOG 的"待用户执行":

- **确切命令**,走 `.env` 的 conda 环境(绝不用系统 python);存在运行入口时经项目运行入口(`execs/run.sh`)调用;
- **产出什么、存哪**(`wkdrs/<run>/…`);
- **该带回什么输出**以便验证完成判据。

把重命令**写成**一个可运行脚本放到 `execs/scpts/<run>.sh`(写文件是轻量的,跑它不是),并让交接里写的命令就是 `bash execs/scpts/<run>.sh`,使它只有一条经过审查的启动路径——启动守卫(规约 §2)也靠它把这次启动和轻量验证区分开:`wkdrs/<run>/` 里没有 `CODE_REVIEW_<date>.md`、或最新一份的日期早于 `EXEC_LOG.md` 里最新的日期时,它拒掉这个脚本,也拒掉 `star-auto` 启动时写的 `wkdrs/<run>/.await` 标记。绝不绕过守卫。没有上文所说的普通运行具体授权时，把命令交给用户。合法的 `star-auto` 授权下，把控制权交还其启动器；启动器记录命令与陈述成本，并且只有审查已更新、未设置 `stop=` 或命令未越过它时才可执行。单凭 `auto=unattended` 不增加覆盖、删除、安装或突破成本线的权限。

没有适用的启动授权时，停下并在简报里告诉用户哪些命令在等他们——把 `star-code-reviewer <叶子>` 作为下一条命令写在它们之上：bug 在算力烧掉之前被抓住，代价是一次审查；等算力烧完才被抓住，代价是算力加重跑。再次调用时先处理那次审查留下的未处理 blocker/major 发现（见本 skill 的续跑规则），然后若这些产出已存在，从完成判据验证处续起（Step 5）。无论是用户、获授权的普通运行还是 `star-auto` 启动，都把确切命令、陈述成本、原始输出/日志路径与代码版本一起保存在 EXEC_LOG 中，使后续验证不依赖摘要，也无需自动重跑。
