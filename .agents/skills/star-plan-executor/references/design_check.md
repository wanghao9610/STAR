# Pre-compute Design Check

Run this against the EXEC_PLAN about to be approved, not against the sub-plan as written. The root plan and the leaf passed their own checklists (`star-plan-coach`'s `plan_rubric.md`, `star-plan-decomposer`'s `subplan_rubric.md`); this asks whether the concrete run now on the page still satisfies them, plus two things neither checklist covers. Evidence is the EXEC_PLAN, the leaf sub-plan, and the root plan's §4 — nothing else. An item whose evidence is not in those three files is `unclear`, never `pass`.

Return one entry per item — `item`, `verdict: pass | fail | unclear`, `evidence` (the quoted line, or the exact statement of what is absent), `fix` — and nothing else. Do not rank, do not decide, do not run anything.

1. **The run produces the number its claim needs** — the leaf's `traces_to` names a root §4 claim or section, and some action here writes the metric that claim is argued from, on the benchmark root §4 names for it. A run producing a different metric, or the right metric on a benchmark the claim does not use, is a `fail` before the compute rather than an `unmeasurable` row after it. (`plan_rubric.md` item 5, re-asked against this run.)

2. **Every number this run reports names its split, and nothing was selected on that split** — each reporting action states which split it reports from, and no checkpoint, threshold, or hyper-parameter in this run is chosen on that same data. Selecting the best epoch on the split the number is reported from is what `star-expt-analyst`'s leakage list catches afterwards, at the price of the whole run. A split named for the report but not for the selection is `unclear`, and the fix is one line saying which split selection uses.

3. **The evaluation benchmark is not plausibly inside the pretraining corpus of the weights §2 names** — the leaf's §2 names weights under `inits/`; root §4 names the benchmarks this run reports on. Say whether the corpus those weights were trained on is stated anywhere in the two plans, and whether it plausibly contains that evaluation data. An unstated corpus is not a `pass`: it is `unclear`, and the fix is one sentence in §2 saying what the weights saw. `unknown` written down is an acceptable answer; an unasked question is not.

4. **The seed or repeat count §5 states is what this run actually launches** — §5 states the seed/repeat policy its threshold is measured under, or explicitly accepts single-seed. Count the configurations the EXEC_PLAN's actions launch. A §5 asking for ≥N seeds against an EXEC_PLAN launching one is a `fail`: the criterion cannot be met by a run that never produces the evidence it names. A §5 that states no policy at all is a `fail` against `subplan_rubric.md` item 6, not this run's problem to solve silently.

5. **Every arm this run compares was given a comparable budget** — where the EXEC_PLAN launches a baseline and a method, or two ablation variants, say what search each got: cells tried, or `defaults, no search`. Unequal effort is not a `fail` by itself; unstated effort is, because the comparison it produces cannot be defended later. A published number quoted rather than reproduced is a `pass` when the plan names its source. (`plan_rubric.md` item 7, made countable.)

6. **An ablation arm differs from its reference in exactly the component the claim names** — for each variant this run launches against a reference, list the fields that differ between their configurations. More than one difference is a `fail` while the claim attributes the delta to one of them: the table it produces will be captioned as isolating a component it does not isolate. Where the EXEC_PLAN does not record enough configuration to answer, the verdict is `unclear` and the fix is naming the two configs in the actions.

7. **What crosses the STOP line has a stated cost, and the plan can afford it** — every action handed back carries GPU×hours or call count and spend, and the root §4 compute budget is stated. A cost this run cannot fund is a decision for the user, not a surprise for the cost table afterwards.

What this check is not: it does not judge whether the research question is worth asking, does not re-open a settled §5 threshold, and does not stop a run. It reports; the confirmation point that follows is where anything is decided.
