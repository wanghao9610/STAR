# 选择性委派格式约定

仅当 Codex 协作工具可用，且工作边界明确、相互独立、确实能从独立上下文或并行执行中获益时才委派。步骤很小、严格串行、与当前改动紧耦合或容易产生文件冲突时，由主 agent 本地完成。不要给每个琐碎动作都创建一个 subagent。

**连贯范围**指至多 3 个 EXEC_PLAN 动作：它们碰同一批文件、拆开就没有意义、共用同一个 check。除此之外都是各自独立的动作。一个范围只委派一次、只检查一次，写进 EXEC_LOG 时每个成员动作各占一行并带上范围标识——没有返回的范围，它的每一行都停在未完成，恢复时就不会把半途而废的范围读成已完成。碰到红线边界要拆开。

**这里的委派是串行的。** 绝不同时跑两个会写文件的受托者：它们会争抢同一份 `EXEC_LOG.md`，而"只 stage 这个动作碰过的文件"在两个写手同时在场时根本没有意义。`star-code-architect` 的并行迁移组彼此独立，有序的计划不是——不要把那条规则搬过来。

**委派之前**，这个动作名下的文件在 git 里是干净的。运行开始时就已经改动过的路径，单独点名为既有改动，并排除在下面所有恢复动作之外：它不归本次运行去回退。

## 交给子代理什么

- **范围**——EXEC_PLAN 中一个内聚目标及其绑定检查。明确写：「只做这个范围，不要继续后续动作。」
- **写入面**——此外一律不碰：`${CODE_NAME}/` 下允许新建或修改的确切文件/模块；`wkdrs/<run>/` 下的产物；`tasks/<plan-name>/` 下的中间文件，绝不碰别的计划的；以及仅限红线动作的那份备用启动脚本 `execs/scpts/<run>.sh`——写它是轻的，跑它不是。要求遵循 `AGENTS.md` 做 精准克制 changes。
- **上下文**——相关的原始计划章节、缺口清单事实和现有接口。若委派用于独立验证，不要泄露预期答案。
- **运行环境**——主 agent 已经解析好的解释器绝对路径，逐字给它。受托者不再自己去读 `.env`。缺包是它要返回的 blocker，绝不是它自己去装的东西（conventions §3.5）。
- **边界**——只跑轻量验证。若动作位于红线，只准备命令并返回，不得执行。

## 必须返回的结构

- `changed`——新建或修改的文件，每个一行。
- `ran`——实际运行的命令及结果，或 `none`。
- `check`——`pass` / `fail` 加证据。
- `blockers`——未解决的阻塞，或 `none`。
- `handoff`——准备好的红线命令，或 `none`。

## 主 agent 的责任

主 agent 必须审查 diff、解决集成问题，并在写入 EXEC_LOG 前重跑或独立验证绑定的检查。子代理自报的通过不能直接作为最终证据。

- 通过 → 记录产物与检查证据，将动作标为 `done`。
- 失败 → 把失败记进 EXEC_LOG，并在重试之前把这个动作名下的文件恢复回去——已点名的既有改动除外——好让下一次尝试从一个已知状态出发。恢复到这个动作开始时的样子，不是恢复到 `HEAD`：checkpoint 提交可能已经被拒绝，那时更早的已验证动作同样没提交，重置到 `HEAD` 会把 EXEC_LOG 已经记为 `done` 的工作一并抹掉。恢复时绝不越出这个动作自己的文件。只有存在具体修正方案时才重试，最多两次。否则该动作标 `blocked`，而它做了一半的改动未必没有价值：恢复之前先问（conventions §7.7——这是把关删除的），记下最终怎么处理的，无论哪种都把路径写清楚，然后停止。没有哪个动作可以留下无人认领的改动。
- 有 handoff → 记入「待用户执行」，不得运行，随后停止。
