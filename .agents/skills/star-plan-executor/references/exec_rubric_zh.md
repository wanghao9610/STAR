# 执行收尾清单

在把一轮判为完成(Step 5)前执行。报告不达标项(≤5,按重要性排序),每条附文件/步骤和具体改法。

1. **完成判据确实被检查过**——子计划 §5 检查有可核验的证据（测试通过 / 指标越过阈值 / 产出存在）记录在 EXEC_LOG，包括确切命令、原始结果或产物、以及对应代码版本；不是口头声称，也不为了让主 agent 声称亲自跑过而重复昂贵检查。

2. **每一步都有真实检查结果**——EXEC_LOG 里不存在标了 `done`、却没有经主 agent 核验通过的步骤；证据可以来自主 agent 自己运行，也可以来自可检查的原次执行：确切命令、退出状态/结果、原始日志或产物、以及对应代码版本。只有受托者摘要不算通过。溯源缺失或过期时重跑最窄检查；整合改变行为、依赖或被检代码时重跑受影响检查。

3. **每次重型启动都已获授权且成本有界**——每个长时/多卡训练、全量评测、大开销 API，要么在"待用户执行"，要么记录了普通运行的具体授权或合法 `star-auto` 启动、陈述成本与适用成本边界。两类授权都不能被推断为不可逆动作授权（`stop_line_rules_zh.md`）。

4. **文件各归其位**——本计划自有的工具脚本与执行过程的中间工作文件在 `tasks/<plan-name>/`,`execs/` 下没有散落的脚本;`EXEC_PLAN.md`、`EXEC_LOG.md` 及生成输出在 `wkdrs/<run>/`;数据在 `datas/`;权重在 `inits/`;运行脚本在 `execs/scpts/`;代码改动只在 `${CODE_NAME}/`。`metds/plans/` 里没有留下任何生成物。scratch 默认保留；只有用户明确要求、且持久产物与证据已提升出去后才删除。

5. **运行走项目环境**——命令都走 `.env` 的 conda 环境;没有系统 python、没有硬编码本地路径。

6. **状态可续跑**——`wkdrs/<run>/EXEC_LOG.md` 反映真实的逐步状态,子计划 frontmatter 有 `exec_status` + `exec_runs`,本轮是追加而非替换上一项。全新 session 能仅凭日志续跑。

7. **改动是精准克制的**——代码 diff 都能追溯到 EXEC_PLAN 的步骤;没有对邻近代码做无关重构或"改进"(`AGENTS.md` §3)。

8. **交接命令可直接跑**——每条"待用户执行"命令都完整(conda 调用、输入、输出路径),并说明该带回什么以便验证。

9. **子计划与实际执行一致**——每条获授权的实质性偏差都已写回子计划 §2–§5 并留有 `## Revision History` 条目(`plan_sync_rules_zh.md`);EXEC_PLAN"与子计划的偏差"和 EXEC_LOG"待同步修正"里,没有既未同步、又未经用户明确决定跳过的行；已有决定的行绝不再次提出。

10. **文档会引用的值都已捕获**——本轮敲定、子计划未写明、且某个 `metds/*.md` 章节会引用的值(超参、初始化、复现命令),要么在子计划里,要么作为一条 ENRICHED 行等待授权决定(`plan_sync_rules_zh.md`)。只有 EXEC_LOG 知道的值,`star-metd-summarize` 只会把它报成一个永久缺口。

11. **没有无人认领或被抹掉的工作**——以 `blocked` 收场的步骤，要在 EXEC_LOG 里写明其 action 自有文件最后怎么了：从 action 起点快照恢复，还是依据用户已有的明确适用决定保留。恢复绝不抹掉既有/用户编辑或原始执行证据，任何一次提交都不会 stage 到某次失败尝试的残留（`agent_dispatch_spec_zh.md`）。
